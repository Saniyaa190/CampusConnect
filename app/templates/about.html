About The Project

CampusConnect Architecture

A robust, scalable college event management system engineered for 2nd-year B.Tech Computer Science Engineering academic demonstrations, viva examinations, and portfolio resumes.

📋

The Campus Problem

Traditional college announcements rely on physical notice boards, scattered messaging channels, and uncoordinated Google Forms. This leads to missed deadlines, overbooked venues, double registrations, and painful manual roster aggregation.

💡

The Engineered Solution

CampusConnect centralizes all academic, cultural, and sports events into a single relational database. It automates registration limits, seat occupancy tracking, duplicate detection, and cancellation seat recovery in real time.

Technology Stack

Python 3.12+ / Flask

Application backend utilizing the Application Factory Pattern and modular Blueprints.

MySQL 8 + PyMySQL

Relational database with strict foreign keys, indexing, and connection pool recycling.

Flask-SQLAlchemy

Object-Relational Mapping (ORM) abstracting SQL queries with cascade deletes and relationships.

Flask-Login & Werkzeug

Session-based authentication, user loader hooks, and secure salted SHA-256 password hashing.

Flask-WTF & WTForms

Server-side data validation, sanitization, and Cross-Site Request Forgery (CSRF) token defense.

Jinja2 + Vanilla CSS3

Lightweight, responsive frontend design system without bulky external framework overhead.

College Viva Defense Cheatsheet

Essential architectural questions and engineering rationales:

Viva Question Engineering Concept & Implementation
Why Flask over Django or Java Spring Boot? Flask provides a lightweight, unopinionated microframework where architectural patterns (factories, blueprints, ORM sessions) can be explicitly demonstrated without bloat or high JVM memory overhead.
How are overbookings prevented? Through database constraints, transaction isolation, and capacity calculation logic (capacity - active_registrations_count) evaluated immediately before persisting bookings.
How is password security maintained? Passwords are never stored in plaintext. Werkzeug uses secure one-way salted hashing algorithms (scrypt/PBKDF2-HMAC-SHA256) resistant to rainbow table attacks.
What happens when a student cancels? Rather than permanently dropping data, the registration record status is set to CANCELLED. This maintains audit logs while dynamically incrementing available seats for other students.
